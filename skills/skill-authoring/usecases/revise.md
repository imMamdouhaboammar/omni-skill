# Revise a Skill: Modifying Existing Skills from Feedback

Operational procedure for revising a skill without architectural drift or bloat.

1. **Understand the Underlying Motivation**: Read user feedback not merely as a literal syntax correction, but as evidence of a deeper unconsidered design dimension (`humanity-and-humanness`).
2. **Re-derive from First Principles**:
   Ask whether the feedback changes the *Why This Skill Is Needed & Target State* section or if an existing rule was insufficiently clear. Re-derive the whole text from that foundation per `redesign-from-first-principles`.
3. **Preserve Unchanged Sections**:
   Do not unnecessarily reword sections that already satisfy the criteria. Maintaining stable structure prevents cognitive disorientation for users and agents.
4. **Fix All Similar Occurrences**:
   If a correction was made in one section, audit all other sections and peer skills for the identical issue per `fix-root-causes`.
5. **Anti-Bloat Check**:
   Reject the temptation to append an ad-hoc warning bullet at the bottom of the file. Integrate the constraint cleanly into the invariant rules.
